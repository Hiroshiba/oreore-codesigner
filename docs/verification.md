# 検証項目

静的検証、CI 上の処理、実機の OS の動作は別々に記録します。
スクリプトが正常終了することだけでは、OS が署名を受け入れることや、自動更新が成功することの証明にはなりません。
未実施の項目を合格として扱わないでください。

## 静的検証と CI

中央リポジトリでは Node.js 22.14.0 と pnpm 10.30.2 を使います。
`pnpm install --frozen-lockfile` の後、`pnpm typecheck`、`pnpm lint`、`pnpm test`、`pnpm format:check` を実行します。
これらの成功と、実際の Secrets を使った署名・公開の成功は別々に記録します。

[verify.yml](../.github/workflows/verify.yml) は `main` への push と pull request で動きます。
format、lint、typecheck、単体テストに加え、`scripts/workflow/test_workflow.py` の fixture 検証、actionlint、Action の 40 桁 SHA 固定、`scripts/workflow` の ShellCheck を実行します。
PowerShell の構文解析は runner に `pwsh` が存在するときに実行します。
このワークフローだけで証明書生成、OS の署名、実際の公開やアプリの更新を確認できるわけではありません。

実際の Actions での `verify` と `sign-release` の実行は未実施です。
ローカルの静的検証や単体テストが成功しても、この二つを実施済みにはしません。

| 確認対象               | 合格条件                                                                                                |
| ---------------------- | ------------------------------------------------------------------------------------------------------- |
| 中央設定               | 未登録の `app_id`、未設定の証明書、許可外のタグ、契約外の設定が公開まで進まない                         |
| ソース固定             | 実行記録からタグと固定されたコミット SHA を確認できる                                                   |
| 秘密情報の分離         | ソースを実行するビルドジョブに署名鍵、App の秘密鍵、公開用トークンが渡らない                            |
| トークンの範囲         | 取得は対象一つの Contents read、公開は対象一つの Contents write に限定する                              |
| 署名と梱包             | アプリ本体へ先に署名し、`--prepackaged` の梱包だけに本体署名を期待しない                                |
| Release set            | メタデータが同じ一式の存在するファイルを参照し、バージョン、サイズ、ハッシュが一致する                  |
| 公開直前の再検証       | `plan-publish --assets-directory` が実 asset と YAML を読み直し、保存済み manifest との不一致を拒否する |
| Windows の配布経路     | 通常 NSIS と WebSetup を別 target で作り、通常 NSIS の更新メタデータだけを公開する                      |
| 公開順序               | 配布ファイルと blockmap が先、更新メタデータが最後になる                                                |
| 正式版の衝突           | 同名で内容が異なる asset を削除せずに停止する。同名で同一 digest なら再アップロードしない               |
| rolling release の置換 | 中央の置換許可と実行時の `true` が両方揃ったときだけ置換する                                            |
| 既存 Release           | Release がない場合に新規作成せず、title、body、tag も変更しない                                         |
| Actions の固定         | 外部 Action の参照がコミット SHA に固定されている                                                       |
| rolling tag の移動     | source 取得後にタグが別の SHA へ動いたら、公開前に停止する                                              |

単体テストでは、正常系だけでなく不正な設定、参照先の欠落、ハッシュ不一致、asset の衝突を確認します。
公開失敗の確認には検証用の Release を使い、正式な配布先を破損させないようにします。
実際の App と Secrets を使った CI の成功記録は、ローカルテストの結果とは分けて残します。

公開の失敗を試すときは、payload と更新メタデータの各段階で止め、旧 asset の復元と、この実行で追加した asset の取り消しを確認します。
曖昧な API 応答、外部の同名 asset、Release ID の変更、期限切れでは、他者の asset を変更せずに停止することを確認します。
復旧用 artifact に journal、バックアップ、ロールバック結果が残り、手動復旧に必要な ID、digest、サイズを照合できることも合格条件です。
archive の展開では、外部へ出るパスやリンクを拒否し、macOS の正当な内部 symlink を保持することを確認します。
署名検証では、macOS の P12 と公開証明書の不一致、Windows の別 thumbprint・publisher、拡張子を変えた PE ファイルも対象にします。

## macOS 実機

連続する二つのアプリバージョンを用意し、OS のバージョン、CPU、公開証明書の fingerprint、両方のソース SHA を記録します。
初回導入はブラウザーで取得した DMG を使い、quarantine 属性を維持します。

| 確認対象               | 合格条件                                                                                                   | 初期の実施状況 |
| ---------------------- | ---------------------------------------------------------------------------------------------------------- | -------------- |
| 初回導入               | 標準の警告と本人による個別許可の操作を記録し、起動と主要機能が動く                                         | 未実施         |
| 本体と内部コードの署名 | 本体、Framework、Helper、ネイティブモジュールなどの署名を確認でき、必要な entitlements が保持される        | 未実施         |
| ZIP 更新               | 同じ bundle ID、証明書、秘密鍵の次バージョンへ Squirrel.Mac 経由で更新し、再起動後のバージョンを確認できる | 未実施         |
| 差分と全量取得         | ログから使用した更新方式を確認し、差分取得が失敗しても全量取得で更新できる                                 | 未実施         |
| 署名後の改変           | 検証用に改変したアプリが署名検証に失敗し、正常な更新として適用されない                                     | 未実施         |
| 別証明書の更新         | 別証明書の更新が同じ署名として扱われず、想定する失敗を記録できる                                           | 未実施         |
| 追加の Mac             | 公開証明書だけで初回設定でき、秘密鍵の転送を要しない                                                       | 未実施         |

macOS のプロファイル実験は、この合格条件から切り離します。
`com.apple.systempolicy.rule` の受理、証明書単位の許可、削除後の挙動を現行 OS で別途確認するまで標準手順へ取り込みません。
プロファイルをインストールできることと、Gatekeeper が意図した規則を適用することは区別します。

## Windows 実機

OS のバージョン、CPU、Smart App Control の状態、公開証明書の fingerprint、連続する二つのアプリバージョンとソース SHA を記録します。
初回導入にはブラウザーで取得した WebSetup を使い、Mark of the Web を維持します。
Smart App Control が強制されている端末を、保護設定の無効化によって合格にしません。

| 確認対象         | 合格条件                                                                                                                                  | 初期の実施状況 |
| ---------------- | ----------------------------------------------------------------------------------------------------------------------------------------- | -------------- |
| 公開証明書の登録 | fingerprint を照合し、対象ストアの Root と TrustedPublisher へ公開証明書だけを登録できる                                                  | 未実施         |
| 初回導入         | WebSetup の署名を確認でき、ダウンロード対象を取得して導入できる。残る SmartScreen の警告と操作を記録する                                  | 未実施         |
| 通常 NSIS 更新   | `disableWebInstaller=true` で通常 NSIS を取得し、再起動後のバージョンを確認できる                                                         | 未実施         |
| 識別情報の継続   | appId、GUID、publisherName が一致し、別アプリとして重複導入されず、設定と利用者データを保持する                                           | 未実施         |
| 差分と全量取得   | ログから blockmap による取得を確認し、差分取得が失敗しても全量取得で更新できる                                                            | 未実施         |
| 署名後の改変     | 検証用に改変したインストーラーが署名検証に失敗し、正常な更新として適用されない                                                            | 未実施         |
| 別証明書の更新   | 期待する publisher または信頼に合わない更新を受け入れず、失敗のログを残す。同じ表示名で信頼済みの別証明書は別条件として受理結果を記録する | 未実施         |
| 追加の PC        | 公開証明書だけで初回設定でき、秘密鍵の転送を要しない                                                                                      | 未実施         |

改変や別証明書の negative test は検証用アプリと検証用 Release で行います。
正規の配布先へ改変済みファイルを公開しないでください。
OS の署名検証と更新クライアントの検証のどちらで停止したかを記録します。
`publisherName` は fingerprint の固定ではないため、同じ表示名の別証明書を必ず拒否することを実装済みの機能として扱いません。

## 記録する内容

実施日、実施者、OS とアーキテクチャ、アプリバージョン、ソース SHA、中央ワークフローの実行 URL、証明書 fingerprint、取得した asset 名、結果、ログの保存先を残します。
OS の警告、初回に本人が行った操作、差分取得と全量取得のどちらを使ったかも記録します。
不明な結果は未確認のまま残し、合格条件を満たした記録だけを導入案内へ反映します。

このリポジトリに実機の成功記録はまだありません。
実装済みの処理と実機で成立した手順を区別し、[README](../README.md)の検証状況も合わせて更新します。
