# 検証項目

静的検査、実際の GitHub Actions、実機での導入と更新を分けて記録します。
このリポジトリではテストコードを実装せず、CI の静的検査と以下の手動確認を行います。
実際の証明書による署名・公開と、実機での起動・更新は未検証です。

## 静的検査と GitHub Actions

[verify ワークフロー](../.github/workflows/verify.yml)で format、lint、型、ワークフローとスクリプトの構文を検査します。
静的検査の成功だけでは、OS の署名処理や GitHub Release への公開の成功を確認したことにはなりません。

実際の App と Secrets を使う確認は、検証用アプリと検証用 Release で行います。

| 確認対象             | 合格条件                                                                                               |
| -------------------- | ------------------------------------------------------------------------------------------------------ |
| 対象リポジトリと入力 | repository と tag で実行でき、App の Selected repositories の範囲だけへアクセスできる                  |
| ソース固定           | 取得時の SHA からビルドされ、公開前にタグが移動していれば停止する                                      |
| 権限の分離           | 取得用は Contents read、公開用は別発行の Contents write で、いずれも対象リポジトリ一つに限定する       |
| ビルド               | 取得・公開用トークンと署名鍵なしでビルドでき、アプリ固有の asar や extraResources が成果物に反映される |
| 署名                 | アプリ本体と内部コードを署名・検証し、ソースのスクリプトやアプリ本体を署名ジョブで実行しない           |
| archive 展開         | 外へ出るパスや危険なリンクを拒否し、macOS の正当な内部 symlink は保持する                              |
| 更新メタデータ       | 実ファイルの参照、サイズ、SHA-512、バージョンが一致し、Windows は通常 NSIS を参照する                  |
| 公開先               | 既存 Release だけを変更し、draft と prerelease に独自制限を加えず、Release の本文などを編集しない      |
| 上書き公開           | 同名ファイルを置換し、配布ファイルと blockmap の後に更新メタデータを公開する                           |
| 公開失敗と再実行     | 途中状態を確認し、同じ実行の失敗したジョブだけを再実行して、同じ署名済み成果物で修復できる             |
| 後始末               | 一時的な署名鍵、キーチェーン、追加証明書を削除し、削除失敗を検出できる                                 |

公開失敗の確認では、配布ファイルと更新メタデータの各段階で停止させます。
同じ実行の保存済み成果物で再実行し、最後に公開された全ファイルを照合してください。
署名の不一致確認には、macOS の P12 と公開設定の不一致、Windows の別証明書や publisher を含めます。
Windows はアプリ本体に含まれる `.exe`、`.dll`、`.node` と、生成した NSIS と NSIS Web のインストーラーの署名を確認します。

## macOS 実機

連続する二つのアプリバージョンを用意します。
初回導入はブラウザーで取得した ZIP を使い、quarantine 属性を保持します。

| 確認対象         | 合格条件                                                                                          |
| ---------------- | ------------------------------------------------------------------------------------------------- |
| 初回導入         | ZIP を展開してアプリを配置でき、OS の警告と本人による許可操作を記録し、起動と主要機能を確認できる |
| 内部コードと署名 | Framework、Helper、ネイティブモジュールを含む署名と必要な entitlements を確認できる               |
| ZIP 更新         | 同じ bundle ID、証明書、秘密鍵の次バージョンへ更新し、再起動後のバージョンを確認できる            |
| 差分と全量取得   | 使用した更新方式をログで確認し、差分取得の失敗時にも全量取得で更新できる                          |
| 改変・別証明書   | 改変したアプリや異なる署名の更新に対する拒否と、停止した検証段階を記録できる                      |
| 追加の端末       | 公開証明書だけで端末を設定でき、秘密鍵の転送を要しない                                            |

system policy profile は[独立した実験](../experimental/macos-system-policy-profile/README.md)として検証します。
プロファイルのインストール成功と、Gatekeeper が意図した規則を適用することは区別してください。

## Windows 実機

連続する二つのアプリバージョンを用意し、Smart App Control の状態を記録します。
初回導入はブラウザーで取得したインストーラーを使い、Mark of the Web を保持します。
Smart App Control が強制されている端末を、保護設定の無効化によって合格にしません。

| 確認対象         | 合格条件                                                                                   |
| ---------------- | ------------------------------------------------------------------------------------------ |
| 公開証明書の登録 | fingerprint を照合し、CurrentUser の Root と TrustedPublisher へ公開証明書だけを登録できる |
| 初回導入         | 通常 NSIS と NSIS Web の署名と導入を確認でき、NSIS Web がパッケージを取得できる            |
| 通常 NSIS 更新   | `disableWebInstaller=true` で通常 NSIS を取得し、再起動後のバージョンを確認できる          |
| 識別情報         | appId、GUID、publisher が継続し、重複導入されず、設定と利用者データを保持する              |
| 差分と全量取得   | blockmap による取得と、差分取得の失敗時の全量更新をログで確認できる                        |
| 改変・別証明書   | 改変や期待しない署名への拒否と、停止した検証段階を記録できる                               |
| 追加の端末       | 公開証明書だけで端末を設定でき、秘密鍵の転送を要しない                                     |

SmartScreen の警告が残る場合は、表示と本人が行った操作を記録します。
`publisherName` の一致は fingerprint の固定ではないため、同じ表示名で信頼済みの別証明書は別条件として受理結果を確認します。
改変したアプリやインストーラーを通常の配布先へ公開しないでください。

## 記録する内容

実施日、実施者、OS と CPU、アプリバージョン、repository、tag、ソース SHA、Actions の実行 URL、公開証明書の fingerprint、取得したファイル名、結果とログの保存先を残します。
OS の警告、初回の許可操作、差分取得と全量取得の結果も記録します。
未確認の結果を成功とせず、実機で成立した手順と実装済みの処理を区別してください。
検証が進んだら [README](../README.md) の検証状況も更新します。
